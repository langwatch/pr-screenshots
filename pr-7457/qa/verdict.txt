WEIRD/UNEXPECTED FINDING (investigated, not a bug):
The real outbound fetch() call is auto-instrumented by Next.js's OWN internal tracer (scope
"next.js", span name "fetch GET https://example.com/"), not by @opentelemetry/instrumentation-
undici/-http/-fetch (Next patches global fetch itself, so those packages never fire here).
That span carries an http.method=GET attribute.
- In the BEFORE build, isHttpRequestSpan() was PURELY a case-insensitive name regex
  (`/^(GET|POST|PUT|DELETE|PATCH|OPTIONS|HEAD)\b/i`) — no scope check, no attribute check at all.
  "fetch GET https://example.com/" doesn't start with a verb, so it was NOT dropped before.
- In the AFTER build, the fix added scope- and attribute-based matching (http.request.method /
  http.method) in addition to a stricter, case-sensitive name regex. That new attribute check
  correctly drops this span after the fix.
So this span going from "kept" (before) to "dropped" (after) is a genuine, correct SIDE EFFECT
of the fix broadening HTTP detection beyond the old narrow regex — not a regression. Confirmed
by reading trace-filters.ts at both commits (see before-isHttpRequestSpan.txt / after-isHttpRequestSpan.txt).

the excludeHttpRequests filtering logic under test.
