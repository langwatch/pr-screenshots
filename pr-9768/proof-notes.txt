## What the scenarios could not show here

- **AC215b on a source row or a card figure.**
  - A trace whose spans are priced at exactly 0 is stored with TotalCost NULL, the same as a trace with no price at all (table above, playground).
  - So the row and the Total cost tile read "–", not "$0.00, some spans not priced". The only surface that shows it is `up-loops` (ac215c.png). Its JS turns NULL into 0.
  - This looks like a gap between the PR's `costText` unit tests, which feed `sum: 0`, and real ingestion. It is worth raising with the PR author.
- **AC215 clause 3, "a card whose figure has no priced span shows the cost setup view instead".**
  - Not seen. With only unpriced spans in scope, the Total cost tile reads "–" (ac215-no-priced-span-tile.png).
  - The simulations-only "Spent" figure on a "Running costs" copy also read "–". That was an earlier scratch capture; it is not kept.
  - I did not trace why the completeness report does not turn this into "Not priced" or the setup view.

- **AC216's "narrowest card width".** Only half-width cards at 1280 px (about 490 px) were captured. No narrower viewport was tried.
- **AC213: SHARE_WINDOW_LIMITED and GRANULARITY_COARSENED.**
  - Not shown. The first needs a project shared from a date.

- **AC214: a chart whose largest value is 0 or 1.** Only largest value 2 was shown. The loops card in ac215c.png has largest value 1 and also has whole-number ticks.

## Setup traps found on this run (fixed in setup.sh)

- ClickHouse needs `<custom_settings_prefixes>custom_</custom_settings_prefixes>`. Without it, the LangWatchQL reconciler fails on `CREATE SETTINGS PROFILE` (UNKNOWN_SETTING).
- `.env.example` sets `FEATURE_FLAG_FORCE_ENABLE`, so add `release_dashboards,release_lwql_workbench` to that list. A default value would be ignored.
- The backend serves the UI only from `LANGWATCH_UI_DIST_DIR`. It is a copy of `apps/ui/dist/client.local`, as `dev/scripts/dev-stack.sh` does.
- `storage-seed` writes the project directly, after the upgrade already ran `analytics:fill-lwql-project-keys` with no projects. So the project has no LangWatchQL key-map row, and every widget reads 0 rows.
  - setup.sh inserts the row that step would write: the sha256-hex of the project's `lwqlKey`.
